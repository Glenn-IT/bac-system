PROBLEM: Login fails with correct username/password
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ You see "Invalid username or password" even when using:
   - Username: admin
   - Password: admin123


WHY THIS HAPPENS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PHP password hashes are dynamic and unique each time they're generated.
The hashes in database.sql are placeholder values that won't work with
the actual passwords. They need to be regenerated on YOUR server.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1: Make sure database is imported
   ✓ Go to: http://localhost/phpmyadmin
   ✓ Verify "bac_system" database exists
   ✓ Verify "users" table has 4 rows

STEP 2: Run the password fix tool
   ✓ Open browser
   ✓ Go to: http://localhost/bac-system/fix_passwords.php
   ✓ Wait for green "ALL PASSWORDS FIXED SUCCESSFULLY!" message
   ✓ You'll see a table with all 4 user accounts

STEP 3: Login
   ✓ Go to: http://localhost/bac-system/public/
   ✓ Login with: admin / admin123
   ✓ Should work perfectly now!


WHAT fix_passwords.php DOES:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This script:
1. Connects to your bac_system database
2. Generates NEW password hashes using PHP password_hash()
3. Updates the users table with correct hashes
4. These hashes will work with password_verify() in login

It sets up these 4 accounts:

│ Auditor          │ auditor      │ audit123     │

TECHNICAL EXPLANATION:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PHP's password_hash() function:
- Uses bcrypt algorithm
- Generates a unique salt for each password
- Creates a 60-character hash
- Cannot be "reverse engineered"

The login uses password_verify() which:
- Takes plain password + hash
- Returns true/false
- Only works with hashes generated by password_hash()

Static hashes in SQL files DON'T WORK because:
- They were generated on a different server
- They have different salts
- password_verify() won't match them
